# Infinite Realms v0.7.6.2 — Biome Resource Reference

## Purpose

v0.7.6.2 makes the existing gathering profiles meaningfully biome-dependent. It extends the authoritative `IR_BIOMES` registry in `js/data/world.js`; it does not add a second resource system. All item definitions remain in the existing `ITEMS` / `IR_V04_ITEM_DATA` tables, recipes remain in `IR_V04_RECIPES`, and concrete enemy IDs remain in `IR_BIOME_ENEMIES`.

## Supported biome profiles and normal gathering actions

| Stable biome ID | Display name | Normal gathering actions | Resource emphasis |
|---|---|---|---|
| `forest` | Deep Forest | Woodcutting, Herbalism | Timber, herbs, biological fiber |
| `plains` | Open Plains | Herbalism | Common plants and existing wild-food item |
| `mountain` | Mountain Foothills | Mining, Woodcutting, Herbalism | Ore, stone, coal; timber and herbs where present |
| `swamp` | Misty Swamp | Woodcutting, Herbalism, Fishing | Herbs, slime gel, fish, wetland materials |
| `desert` | Sunscorched Desert | Mining, Herbalism | Stone, ore, coal, sparse herbs |
| `snow` | Snowbound Reach | Mining, Woodcutting, Herbalism, Fishing | Ore, stone, timber, cold-region herbs, fish |
| `coast` | Windworn Coast | Herbalism, Fishing | Herbs, fish, coastal scrap |
| `river` | Riverlands | Herbalism, Fishing | Herbs, fish, riverbank food/materials |
| `woodland` | Rolling Woodlands | Woodcutting, Herbalism | Timber and herbs |

The existing risky-area mining exception is preserved: any location with `risk >= 28` may expose mining even when mining is not in that biome's normal availability list. The cave compatibility rule is also retained. For sites where this exception applies, the biome-specific mining pool is used rather than a generic fallback.

## Runtime consumers and safety

- `irBiomeGatheringItems(siteOrId, activity)` returns valid existing item IDs from the resolved biome's pool. It returns an empty array when the biome cannot be resolved; it does not silently return woodland items.
- `irBiomeGatheringAvailable(siteOrId, activity)` preserves normal profile eligibility and the existing risky-area/cave mining exception.
- `irBiomeResourceItems(siteOrId, 'forage' | 'scout')` expands the authoritative profile weights and excludes invalid item IDs.
- `ir04Gather(method)` is guarded by `js/game/38-biome-resources-gathering-v0.7.6.2.js`. It resolves `state.world.siteId` exactly and refuses missing/invalid site or biome references before spending time or energy. Valid calls delegate to the existing action, preserving its skill/risk success formula, drop quantity, tools/skills/talent behavior, carrying capacity, XP, and item-condition rules.
- `irExplore('forage' | 'scout')` uses the same current-site and valid-resource checks before delegating to existing exploration behavior.
- `irValidateBiomeResourceIntegrity(world?)` checks resource and gathering item IDs, profile availability metadata, duplicate/missing site IDs, unresolved biome references, and current/known/visited site references.

An invalid biome or dangling current location does not award materials. The validator reports bad saved data; it does not repair or rewrite the site's `biomeId`. A legacy cave can resolve to the existing mountain profile without changing the saved cave identifier.

## Preserved behavior

No new item IDs, recipes, item weights, equipment definitions, racial-affinity fields, or environmental systems are introduced. The previous action costs remain 11 energy / 2 days for mining and 8 energy / 1 day for other gathering actions. A valid failed attempt still spends the normal cost; an unavailable or invalid action spends none. The accepted v0.7.6.1 standalone is kept unchanged as the rollback point.
