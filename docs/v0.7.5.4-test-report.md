## v0.7.5.4-specific coverage

The world-generation suite creates 24 worlds across six seeds and four starting circumstances; checks deterministic generation; compares generation output against the v0.7.5.3 generator; checks route-graph connectivity and endpoints; repeats geographic enrichment to check idempotence; tests saved v2 world reuse; tests enrichment of pre-geography v2 saves; performs three serialize/normalize/reload cycles; verifies current location, visited/known state and discoveries; verifies malformed route endpoints trigger fallback normalization; and validates reference-only settlement/biome indexes.

The full-script integration suite executes the actual application script sequence (excluding the final DOM boot call) in a minimal DOM shim. It confirms that the generated world passes the geographic validators, the existing travel-confirmation execution updates current/visited/discovery state, route travel can queue an existing encounter, gathering still yields resources based on the current site's biome, location-bound NPCs do not gain duplicate IDs from repeated initialization, and point-of-interest discoveries still refer to existing site records.

## Browser test caveat

Node tests exercise the full application script sequence with a minimal DOM shim and simulate JSON save/load through the production normalizer. They do not prove that the real browser page starts visually or that `localStorage` persists through a full browser restart. A headless Chromium attempt was made with the built HTML and with `about:blank`; both timed out with exit code 124 and zero-byte DOM dumps. Because the control page failed in the same way, this is an environment limitation and not evidence of either app success or an app-specific failure. Manual browser startup and real localStorage save/load remain open checks.
