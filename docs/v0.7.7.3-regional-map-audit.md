# Infinite Realms v0.7.7.3 — Regional Map Architecture Audit

## Starting point

The accepted input is v0.7.7.2. The earlier v0.7.7.1 shared-data accessors and v0.7.7.2 atlas remain in place. The new layer is loaded after `js/game/44-world-map-v0.7.7.2.js` and before the application boot module.

## Grounded map data

- `js/data/world.js` contains the existing `IR_BIOMES` profile registry.
- The procedural generator builds a 7×7 region with 49 site records. Site `x`/`y` values are regional chart coordinates, not world-scale coordinates or surveyed land boundaries.
- Each site keeps its existing IDs, biome reference, discovery/visit fields, and local `routes[]` records.
- `world.region.routes` is the canonical geographic connection registry. Its endpoints resolve to existing site records through the existing stable geographic-resolution helpers.
- The gameplay travel lookup continues to use the current `irRouteBetween` helper and existing route data. The new renderer does not introduce a parallel route graph.
- Generated undirected edges are represented in both endpoints' `site.routes[]` records. The regional chart now requires that reciprocal pair to exist in addition to the canonical regional edge. Explicitly directed edges require an actual forward traversal record.

## Presentation rules

1. Plot only sites with valid recorded regional coordinates and actual player knowledge: current, known, visited, or explicitly discovered. A single explicit intelligence lead may be shown through the existing intelligence marker path; it does not reveal its neighbors.
2. Unknown/undiscovered sites are not rendered as markers, route endpoints, terrain patches, labels, or details. The fog pattern is generic and has no dependency on undiscovered site coordinates.
3. The current site is always identifiable, but if its saved record is not marked visited/discovered, the map and local detail sheet do not expose its stored name, settlement type, risk, description, or service list.
4. Known unvisited locations show the supported terrain classification, not a hidden proper name, settlement classification, description, or danger value.
5. Selecting a marker updates transient selection and inspection content only. The travel control is shown only for a known destination with both a real gameplay travel route and a verified visible regional edge.
6. Missing coordinates move a known location to an explicit list; they are never replaced with `0,0` or fabricated positions.
7. Optional continent, country, hierarchy, route, biome and site details are guarded. Absent optional geography does not crash the atlas/regional/local renderers.
8. Atlas, regional and local transitions preserve a still-inspectable selected `geoId`; stale/unknown selections fall back to the current site. Map-scope state is not written into the saved world.

## Why several visible features are absent

The accepted data does not contain surveyed river paths, coastline polygons, mountain-range outlines, road polylines, route crossing locations, country/kingdom boundary geometry, or settlement street/building layouts. The code therefore draws no river, coast, ridge, crossing, boundary or street as if its location were known. Biome patches are approximate illustrations centered on recorded site coordinates. Straight route connectors represent graph connectivity only; they are not presented as a traced road/path.

The local layer is a record-driven detail sheet exposing only existing service records and known exits. It is intentionally not a fake spatial local map.

## Integrity constraints

- No world-generation or geographic records are created by rendering.
- No IDs or connections are duplicated into a new map data structure.
- No travel formulas, transport options, route eligibility or danger calculation are implemented here.
- No discovery progress is granted or erased.
- No map fields are added to the save schema.

## Remaining model limitations

The source generator has one populated region and no populated continent/country set, so the world-scale atlas can navigate to this region but cannot truthfully render a continental/world landmass. Local settlement geometry also does not exist. These are prerequisites for future geographic data work, not reasons to manufacture shapes in this subversion.
