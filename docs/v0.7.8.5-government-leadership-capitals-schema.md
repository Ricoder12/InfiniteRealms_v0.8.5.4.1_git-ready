# v0.7.8.5 Government, Leadership, and Capital Data Contract

## Political entity fields

- `governmentType` (optional enum): `monarchy`, `council`, `republic`, `tribal-leadership`, `city-state-administration`, or `other`.
- `governmentDescription` (optional string): descriptive text only.
- `leaderNpcId` (optional string reference): ID of an existing person/NPC; never a nested copied NPC object.
- `leaderTitle` (optional string): descriptive title for the referenced leader.
- `capitalSiteGeoId` (existing optional field from the political-entity foundation): stable geographic site ID; the site record remains authoritative for the capital's name and region.

None of these fields is required. No government type, ruler, title, capital, or political entity is automatically seeded.

## Leader identity resolution

`irResolvePoliticalLeader` searches existing NPC/person records in the provided character context, the existing `world.npcs` collection when present, and `world.v06.changes` persistence overlay. The stable ID remains the reference. Overlap between live and saved overlay data is treated as one identity; ambiguous duplicates within a given store or an unresolved ID are reported. It does not create NPCs or change relationships.

The current game does not have a single comprehensive global NPC directory. A person can be used as a political leader only when their existing identity is materialized in one of the supported saved stores. Unmaterialized/generated residents may not resolve as an off-site ruler until the game has a global person registry.

## Capital validation

A non-empty `capitalSiteGeoId` must resolve to one existing site using the previous political entity validator. If an entity has explicit `ownerPolityId` or `governingPolityId` region references, the capital site must fall within one of those referenced regions or their descendant regions. If the entity has no territory assignments yet, territorial placement is unknown and is not inferred. Entities are allowed to have no capital.

## Controlled region counts

`irGetPoliticalEntitySummary` counts regions with explicit owner/governor references. It does not infer territorial control from adjacency, parentage alone, or `polity.regionIds` (which are geographic anchors in the existing schema). `controlledRegionCount` is `null` when explicit territory references are absent, rather than claiming a known count of zero.

## Persistence

The fields are additive optional metadata. Existing `normalizeSave` is wrapped to validate what is present. There is no schema version bump and no migration. Missing fields remain missing and the related summary values are `null`/unassigned.
