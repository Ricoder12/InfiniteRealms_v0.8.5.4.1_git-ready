# Infinite Realms v0.8.3.6 — Implementation and Test Report

## Result

The v0.8.3.6 Association tab and shared assignment gate are implemented in a separate candidate tree. This candidate is **not accepted**. The latest explicitly accepted baseline remains v0.8.3.4; v0.8.3.5 was a verified candidate, not an accepted release. Implementation used the verified v0.8.3.5 source candidate and preserved it and the accepted v0.8.3.4 artifacts unchanged.

## Implementation

- Added a top-level Association tab with overview, player membership, personal rank, Association standing, separate public reputation, known Grandmaster and branch staff, registered branch locations, available contract and duty offers, active assignment details, completion/history, and service links.
- All shown values come from existing organization, NPC, character, rank, membership, contract, and duty records. No global member registry or complete leaderboard is implied. Missing leadership, unresolved NPC references, and absent roster records are stated plainly.
- Contract offers reuse `ir0834OfferMarkup` and the existing contract service; duty offers reuse the existing templates and duty action service. The tab can open branch boards and personnel interactions only when their real references resolve and the receptionist is present at the configured location.
- Added a derived shared assignment gate at both authoritative acceptance functions: `ir0834AcceptContract` and `ir0833GuildAction` for duty acceptance. It blocks contract-with-contract, duty-with-duty, and cross-type overlap; it also rejects nested/repeated acceptance while an acceptance call is in progress. Disabled controls are supplemental; service calls enforce the rule.
- The active slot is computed from authoritative active contract and duty rows. No duplicate assignment flag or save migration was added. More than one pre-existing active row is preserved and shown as a conflict; acceptance remains blocked while existing records can still be inspected or managed through their current service.
- Duty completion/credit and contract completion/reward continue through the existing lifecycles. The slot is released only after records transition to the existing saved terminal state. Existing duties retain cancellation and the 14 in-game day expiry. Existing contracts have active/completed states and no cancellation or expiry rule; no new terminal policy was invented.

## Save compatibility

No save fields, schemas, migrations, or world records were added. The tab reads the existing records without calling migration helpers; opening it does not initialize adventurer progression or invoke save-side migration. Assignment checks preserve invalid/quarantined data and block acceptance when it cannot be safely read. Existing save normalization and lifecycle tests were included in the full suite. No user-exported save files were supplied or tested.

## Test results

- Node test files: **50 passed, 0 failed**.
- JavaScript syntax checks under `js/`: **84 passed, 0 failed**.
- Normal standalone build: **PASS**.
- Full-source production-path tests rendered the Association tab and verified it did not mutate progression; they also verified that an active duty blocks direct contract acceptance and another duty, while the existing duty board remains reachable for management.
- Shared-gate focused tests covered contract-active and duty-active blocking, cross-type calls, nested acceptance, pre-existing multiple assignments, quarantine, read-only tab rendering, and due-duty expiry including failed expiry-save rollback.
- Standalone structure/smoke checks: **6 passed, 0 failed**.
- Interactive browser test: **NOT TESTED**. Screenshots: **NOT CAPTURED**.
- User-exported save compatibility: **NOT TESTED**. Existing automated persistence/normalization fixtures passed as part of the 50 test files.

The suite initially exposed a legacy production-path fixture that attempted to keep multiple duties active at once. The fixture now cancels/completes each duty under the already-existing lifecycle before starting the next, so it tests the new one-active rule rather than depending on concurrent assignments. Release-title and load-order checks were advanced to v0.8.3.6 while retaining their ordering assertions.

## Known limitations

- No authoritative global adventurer registry exists. The Association page shows the player's own membership record only and explicitly says the roster is incomplete.
- Many worlds have no configured Association Grandmaster or delegated examiner. The v0.8.3.5 examination service remains unavailable in those worlds; the tab reports the missing/unresolved authority rather than inventing an identity.
- A branch's receptionist/guildmaster interactions require the existing referenced NPC and configured site. Other branches link to the existing World map; no travel action or city overview is invented.
- Existing contracts have no cancellation, failure, or expiry state. A contract therefore occupies the shared slot until its existing verified turn-in completes. No alternate release rule was introduced.
