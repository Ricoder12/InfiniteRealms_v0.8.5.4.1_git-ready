# Infinite Realms v0.7.6.1 — Biome Profile Reference

## Authoritative source and identity

`js/data/world.js` → `IR_BIOMES` is the single authoritative biome-property registry. The registry key (`forest`, `plains`, etc.) is the stable biome identifier. A duplicate `id` field is deliberately not stored in each profile. Generated and saved sites continue to store the existing `biomeId`; their legacy `biome` and `opportunities` fields are retained for compatibility but are not the authoritative source for new UI labels or biome-property lookups.

`irResolveBiomeProfile(value)` resolves an existing `biomeId`, a current profile name, or a known legacy label. `irBiomeProfileForSite`, `irBiomeIdForSite`, and the accessors below read the shared profile without copying profile objects onto sites and without changing the saved assignment. An unknown/invalid biome is reported by `irValidateBiomeProfiles`; read-only accessors use the documented safe woodland profile for descriptive data. Forage chance falls back to no biome modifier (`0`), while the historical gather-item fallback remains `['scrap','herb']` for invalid IDs. These runtime defaults do not silently repair the saved `biomeId`.

## Fields

| Field | Meaning / consumer |
|---|---|
| Registry key | Stable biome ID; matches existing sites' `biomeId` |
| `name`, `icon`, `desc` | Canonical display and description data |
| `terrain` | Broad terrain class; descriptive metadata only in this version |
| `conditions` | Stable tags describing conditions; no survival damage or simulation is attached |
| `habitats` | Generic habitat categories; a vocabulary for future use, not a monster simulator |
| `opportunities` | Existing local activity descriptions, now read from the profile for display |
| `resources` | Weighted item records for existing forage/scout actions. `forageWeight` and `scoutWeight` preserve the old list multiplicities; `category` records broad resource categories |
| `foragingChanceModifier` | Existing chance modifier reused by the forage action; no values changed |
| `gatheringPools` | The old item arrays for mining, woodcutting, herbalism, and fishing, moved from a per-action duplicate table into each profile. Repeated IDs intentionally preserve weighting |
| `gatheringAvailability` | Existing UI availability by action, formerly maintained in the gathering panel. Mining still has the original high-risk (`risk >= 28`) and legacy-cave exceptions |

The existing `IR_BIOME_ENEMIES` table in `js/data/enemies.js` remains authoritative for concrete enemy IDs. Profiles do not duplicate enemy definitions. There is no supported travel-speed/route-cost biome modifier today; route distance, transport, fare, time, and risk formulas remain in the existing travel system.

## Accessors and consumers

- `irBiomeProfileForSite(siteOrId)`: returns the canonical profile object for read-only access.
- `irBiomeIdForSite(siteOrId)`: returns the stable ID, or `null` when only a fallback profile could be selected.
- `irBiomeResourceCategories(siteOrId)`: available resource category tags.
- `irBiomeResourceItems(siteOrId, 'forage' | 'scout')`: expands the existing resource weights into the prior random-pick arrays.
- `irBiomeForageChanceModifier(siteOrId)`: existing forage chance modifier.
- `irBiomeGatheringItems(siteOrId, activity)`: clone of the canonical gathering item pool.
- `irBiomeGatheringAvailable(siteOrId, activity)`: existing button eligibility, including mining exceptions.
- `irBiomeHabitatCategories(siteOrId)`: descriptive habitat tags.
- `irBiomeEncounterIds(siteOrId)`: looks up the pre-existing `IR_BIOME_ENEMIES` pool without duplicating it.
- `irBiomeTravelContext(fromSite, toSite, route)`: reads endpoint profiles plus existing route terrain; it does not add travel modifiers.
- `irValidateBiomeProfiles(world?)`: checks required fields, IDs, item definitions, weights, availability metadata, encounter references, and existing site assignments. It reports issues without repairing the save.

The profile validator is called after existing world generation and after the existing save normalization chain. This check is diagnostic only and does not regenerate a world, attach profile copies to sites, or add fields to saved-world instances. No save-schema migration is introduced by v0.7.6.1.
