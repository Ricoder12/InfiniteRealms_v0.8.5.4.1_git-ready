# Infinite Realms v0.8.3.2 — Rank Ladder and Eligibility

## Source and scope

This build starts from the verified v0.8.2.5 source archive. v0.8.3.1 was an audit-only task, not a source release. The new rank module is `js/game/67-adventurer-rank-eligibility-v0.8.3.2.js`, loaded after the v0.8.2 guild systems and before boot.

This step defines the approved stable order `F`, `E`, `D`, `C`, `B`, `A`, `S`, `SS`, `SSS`, and provides a read-only eligibility API. It does not initialize a rank in new characters, migrate saves, grant a promotion, run an exam, track completed duties/contracts, or change guild contract acceptance.

## API

- `IR_V0832_RANK_DEFINITIONS`: immutable rank IDs, display labels, and ordering.
- `IR_V0832_DEFAULT_REQUIREMENTS`: immutable requirements for target ranks. All four categories remain marked unresolved until approved: completed contracts, completed duties, guild standing, and passing the applicable examination.
- `ir0832ValidateRankDefinitions(definitions?)`: checks the exact nine-rank ordering and ordinal values.
- `ir0832EvaluateRankEligibility(progressionState, targetRankId?, configuration?)`: derives the next rank from `progressionState.currentRank`, rejects invalid/skipped targets, evaluates every configured requirement, and returns `eligible`, a status, and structured blockers. The default configuration is unresolved and therefore cannot grant eligibility. The function does not mutate the input.
- `IR_V0832_CONTRACT_RANK_RULES` and `ir0832ContractRankEligibility(contractId, currentRankId, rules?)`: stable-contract-ID keyed gate data/API. The three existing offer templates (`route-survey`, `monster-signs`, `supply-ledger`) each have unresolved rank ranges; the helper fails closed and is not wired into the v0.8.2 acceptance handler.

The progression input shape expected by an explicitly configured evaluator is:

```js
{
  currentRank: 'F',
  completedContracts: [{ id: 'stable-contract-id', status: 'completed' }],
  completedDuties: [{ id: 'stable-duty-id', status: 'completed' }],
  guildStanding: 0,
  passedExaminations: ['E']
}
```

An absent rank, statistic, list, or unresolved configuration never satisfies a requirement. An examination can be marked not applicable only through an explicitly configured `passedExamination: { status: 'configured', value: false }`; a missing or unresolved exam rule remains blocked. Guild standing is supplied separately from personal rank and accomplishment fields. This schema is an API contract only; it is not written into character saves in this version.

## Unresolved design decisions

- Whether new characters start at F and how older saves acquire a starting rank.
- Numeric per-rank contract, duty, and guild-standing thresholds.
- Exam rules and which transitions require an exam.
- Qualifying completion sources and contract rank minimum/maximum ranges or exceptions.

Until these decisions are approved, shipped defaults intentionally return unresolved/ineligible results. No promotion or contract acceptance behavior is gated by rank in this release.

## Validation

The v0.8.3.2 tests check ladder order, malformed/unknown ranks, sequential next-rank rules, SSS termination, missing statistics, unresolved fail-closed defaults, configured test cases, unique completion-ID counting, deterministic read-only evaluation, contract range validation, and no contract workflow change. Full Node regression and JavaScript syntax results are recorded in the release report.
