## Save compatibility defect found and fixed

An initial browser round-trip check failed. The older `ir0755PrepareSaveInput` save compatibility function rewrote every non-primary `site.regionId` to the primary region. That behavior would silently erase a valid nested regional assignment on save/load. The v0.7.8.3 module now wraps the preparation boundary and restores only region IDs that resolve uniquely in both the original and prepared region trees. Invalid/dangling IDs retain the existing conservative primary-region repair, along with an explanatory compatibility notice. A valid unchanged save does not get marked migrated solely because of that temporary rewrite.

After the fix, the regional browser suite passed **15/15**, and the full save compatibility suite passed **21/21**. An added Node test separately verifies that a valid nested assignment does not create a false save-migration change.

## Known limitations

- No user-exported player save was supplied. Compatibility uses saves generated from accepted older builds and a deterministic extensive-exploration fixture.
- No political/regional content is seeded. The child-region hierarchy is a data foundation only; the World map does not display country ownership or boundaries in this release.
- There is still one canonical primary `world.region` object for sites and routes. Nested regions are metadata records, not separate world containers with own roads/sites.
- No save-schema version bump was made. Save compatibility is additive and conservative, but real-world old saves with malformed or ambiguous IDs remain dependent on the existing compatibility validation/fallback rules.
