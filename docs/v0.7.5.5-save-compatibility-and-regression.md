# Infinite Realms v0.7.5.5 — Save Compatibility and Regression

## Scope and change log

Based on the accepted v0.7.5.4 source tree. Added `js/game/36-save-compatibility-regression-v0.7.5.5.js` and its regression tests. Older modules and the original v0.7.3.6 baseline were not edited.

The patch is intentionally limited to compatibility and validation:

1. Wraps the existing geographic hierarchy index rebuild so unrelated/unknown `world.geography` extension fields survive a rebuild. Supported reference indexes are still recomputed from authoritative site records.
2. Adds `ir0755ValidateGeographicIntegrity(world, character)`, checking the established ID/hierarchy validators plus valid biome keys, settlement/POI IDs and indexes, local route stable IDs vs. existing `route.to`, global route endpoints, discovery/current/known/visited pointers, and NPC location refs.
3. Adds conservative pre-normalization preparation for eligible v2 worlds. Missing geographic IDs are enriched without replacing legacy site IDs. A missing/dangling `site.regionId` is repaired only to the primary region that already contains the site. A local `toGeoId` is repaired only when the existing legacy `route.to` uniquely resolves.
4. If the current-location pointer is invalid, restores it only from the last valid entry in the save's `visited` history. If no valid history can establish a location, it does not guess within the saved map: the established deterministic seeded fallback is used, and a compatibility notice is saved.
5. Invalid journal discovery locations are retained as `unresolvedSiteId` rather than being rewritten to the current location by the older normalizer.
6. Invalid or ambiguous route endpoints are not redirected through potentially stale numeric array indexes. If the v0.7.5.4 structural reuse gate rejects that map, the existing seeded fallback path is used and a notice is stored.
7. Compatibility notices and the validator's results are kept in `world.geographyCompatibility` and a feed warning when a migration needs attention. The recovery field distinguishes `saved-world-reused` from `seeded-fallback-used`.

## Authoritative data sources

| Concept | Authoritative source | Reference/index role |
|---|---|---|
| World identity | `world.id` and saved `world.seed` | Stable world scope; seed remains the generation input |
| Region and sites | `world.region` and `world.region.sites` | Authoritative current regional geography; site record is not duplicated per map view |
| Site identity | Existing `site.id`; stable `site.geoId` | Legacy IDs remain authoritative for current player/NPC/travel fields; geo IDs add stable geographic references |
| Site biome | `site.biomeId` (and existing `site.biome` display data) | `world.geography.biomeIds` is only a derived list of IDs, not an independent biome owner |
| Settlement | The `site` whose `type` is `settlement`, including its `settlementId` | `world.geography.settlementRefs` only indexes `{ id, siteGeoId }` |
| Point of interest | Existing landmark site and its `pointOfInterestId` | `world.geography.pointOfInterestRefs` only indexes `{ id, siteGeoId }` |
| Travel connection | `world.region.routes` (global graph) and each site's existing `routes[].to` (travel destination) | Stable route refs enrich the connection; they do not replace the legacy travel target |
| Player current/known/visited state | `world.siteId`, `world.known`, `world.visited` | These continue to use legacy site IDs to preserve gameplay |
| Journal discovery | `world.journal.discoveries[].siteId` | Refers to an existing site. When unresolved, `unresolvedSiteId` records the original value without a false reassignment |
| NPC geography and schedule | NPC `homeSite`, `workSite`, `restSite`, `socialSite`, `siteId`/`locationId` | References existing site IDs; warning-only where automatically correcting would risk relocating an NPC incorrectly |

## Migration behavior

The outer save schema version is not bumped. The existing `normalizeSave()` chain remains in place; v0.7.5.5 wraps it. A v2 world that passes the v0.7.5.4 reuse gate is reused rather than regenerated. Missing geography fields are enriched. Repeated normalization is covered by tests and is idempotent for the supported records/indexes.

Conservative repairs are purposefully narrow. Existing, non-empty IDs are not generally renamed. The existing legacy route destination is not rewritten. A dangling route that cannot be uniquely identified is not redirected. If a map is structurally unsafe for reuse, the code follows the existing deterministic-generation fallback path and records why when the compatibility layer detected the issue.

## Limitations

- No user-exported player-save JSON was present in the accessible project/files during this task. Cross-version save testing therefore uses a synthetic state created by executing the actual v0.7.3.6 source, plus generated v2 save fixtures. This is not evidence that every individual real-world save has been tested.
- The automated persistence test uses a `localStorage`-compatible Node shim. A genuine browser session/restart has not been verified; the available Chromium headless control timed out on `about:blank` too.
- Unknown NPC location references are reported as warnings, not auto-reassigned, because there may be custom or future semantics behind those values.
- If a save has no resolvable current site and no valid visited location, the prior saved map cannot be retained safely under the current normalizer contract. The deterministic fallback is signaled rather than presented as lossless recovery.
