# v0.7.7.8 Migration Details

## Formal migration status
**No formal save-schema migration was required or introduced.** The existing save schema/version behavior remains in place, and the established v0.7.5.5 geographic compatibility normalizer remains authoritative.

## Optional-field defaults
The new compatibility wrapper only fills properties when they are absent or structurally invalid:

- `world.visited`: if absent, infer valid site IDs from current site and existing `discovered`/`visits` records.
- `world.known`: if absent, infer the current, visited/discovered sites and valid neighbors already present in the saved route graph.
- `world.journal`: ensures an object exists and initializes missing `knownLocations`, `visitedLocations`, `discoveries`, and `rumors` arrays.
- `character`: ensures missing `attrs`, `skills`, `inventory`, `equipment`, and `relationships` containers, plus `npcs` and `discoveries` arrays.
- `world.v0723`: initializes the already-existing optional lead store (`schema`, `activeLeads`, `history`) before map rendering; existing valid lead data/history is preserved.

Defaults are not written over valid existing arrays or object contents. The saved world is not regenerated, and valid geographic identifiers are not rewritten by this module.

## Transient UI state
When `state` is replaced by a loaded save or new game, the compatibility layer resets map scope to World/atlas and resolves the selected marker from the new current site. This avoids retaining a stale selection from the previous world. Those UI values are intentionally not stored as save progress.

## Idempotence
The new Node compatibility test normalizes the same state repeatedly and checks that the result remains stable, that existing valid IDs/records remain intact, and that route/location identifiers remain unique.

## Risks and boundaries
The wrapper depends on the application's existing `normalizeSave`, `makeInitial`, `clone`, and `render` integration points, so script load order is important. Existing base geographic validation still handles malformed mandatory region/site/route structures; this patch does not guess a replacement for ambiguous or corrupt required IDs. No user-exported save was available for testing, so coverage does not establish universal compatibility with every real-world save.
