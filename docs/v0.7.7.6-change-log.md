# Infinite Realms v0.7.7.6 — Character Status Window

## Update: preserve the accepted Character screen and append status details

The v0.7.7.6 renderer is append-only. It calls the previously accepted Character renderer unchanged, then appends the additional current-condition, location/environment, and equipment-bonus section below the original screen.

### Changes

- Preserved the original Character view: character visual/equipment, natural talents, attributes, learned skills, progression, magic, and history remain in their original order.
- Appended current health and energy with their existing maximum values, and any existing hunger/mood fields.
- Resolved the current location by the canonical `world.siteId` and the existing unique geographic site record; the renderer no longer invents a generic current-location fallback when the site can be resolved.
- Listed currently recorded character-specific conditions/effects only when present in existing character state.
- Displayed the active environmental hazard returned by the existing hazard system when one applies.
- Appended an eight-slot equipment overview reading `character.equipment` and the existing item definitions. Known numeric bonuses are shown only when present in existing weapon/equipment definitions. The Inventory screen remains the place to manage equipment.
- Corrected the runtime document title and visible shell release label to v0.7.7.6.
- Refreshed four historical map/standalone test expectations that were still requiring the old v0.7.7.5 release title. Their map behavior assertions were not changed.

### Scope deliberately not added

No new character creation fields, attributes, skills, conditions, equipment slots, progression rules, balance rules, or save-schema changes were added. The Skills, Inventory, travel, combat, and save systems are not replaced.

### Remaining completion work

The focused browser and regression checks pass. The full manual completion gate still needs gameplay verification of training, actual equip/unequip actions, damage and recovery, time advancement, real active condition application/removal, and loading a pre-existing player save.
