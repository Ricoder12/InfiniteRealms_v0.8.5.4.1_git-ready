# Infinite Realms v0.7.3.2 — Witness-Based Reputation Test Report

## Patch scope

Added `js/game/28-witness-based-reputation-v0.7.3.2.js` after the NPC memory reliability layer and immediately before boot. The patch is isolated; no existing combat, death, reputation, guard, memory, reward, or save implementation file was edited.

### Affected functions and new helpers

- Wraps `ir0724RecordCrime` to track the base penalty, witness IDs, settled public penalty stage, and report idempotency. Reusing an existing `incidentId` updates the report/knowledge state without repeating personal consequences.
- Wraps `irCombatEnd` for NPC-assault victory to re-check witnesses at the time of death and prevent a second resolution of the same crime ID. The established assault penalty and additional public murder escalation remain distinct stages; each stage is applied at most once.
- Adds `ir0732ReportCrimeRecord(crimeId, reporterId)`. It accepts a surviving victim only when their existing personal memory/last-harm record supports knowledge, or an NPC recorded as a witness. It does not add a UI flow or allow unrelated NPCs to report secret events.
- Adds `ir0732WitnessIds`, `ir0732BasePenaltyFor`, and crime lookup helpers.
- Wraps `shell`, `topbar`, `persist`, and `normalizeSave` only to update visible/save version metadata to 0.7.3.2. `IR073_SAVE_SCHEMA` remains 8.

## Known limitations

- No new visible reporting menu was added. `ir0732ReportCrimeRecord()` is a guarded integration hook for a valid victim/witness callback; the existing guard report UI continues to report local criminal leads, not the player's own crimes.
- Witnessing is based on the existing current-location/presence and schedule rules; the game does not model line of sight or sound occlusion.
- Real save/load and full in-game regression testing remain outstanding because the automated browser environment did not produce a DOM result.
