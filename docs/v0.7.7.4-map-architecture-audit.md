# Infinite Realms v0.7.7.4 — Local Map Architecture Audit

## Starting point

The implementation starts from the accepted v0.7.7.3 standalone and its split source. The local map is rendered as an enhancement to the existing `ir0773RenderLocalView` panel. The existing atlas, regional chart, travel preview, service handlers, and navigation remain the sources of gameplay behavior.

## Existing records used

- The current location is resolved through the existing current-site/world map model and stable geographic identifiers.
- Site `type`, `settlementType`, `biomeId`/legacy biome labels, and the registered `IR_BIOMES` profile determine the type and biome presentation.
- `site.services` is the sole source of interactive facility markers. Known aliases such as `smithy`/`forge` collapse into the existing forge presentation rather than creating multiple businesses. Unregistered service IDs are not turned into clickable buildings.
- Existing NPC records are read from character/world state. A worker is only shown where an existing NPC record references this site through its recorded work/home/origin references and its occupation is known. The local map does not call NPC-generation routines.
- Recorded landmark point-of-interest metadata directs to the existing Adventure view. Other service buttons reuse existing application tabs or action names (`local-rest`, `jobs-modal`, `local-healer`, `ask-rumor`, etc.).
- Outgoing connections, distance, travel buttons, and known destination references remain in the accepted regional/local detail layer and existing travel route records.

## Presentation architecture

`js/game/46-local-map-v0.7.7.4.js` wraps the accepted local-detail renderer and inserts an illustrative scene. Placement slots are deterministic from existing world/site identity and settlement type; positions are transient presentation only and are not written to saved state. `css/world-map.css` provides biome palettes and settlement-scale layout styling.

Decorative homes, paths, central green/plaza, terrain props, compass, and water patches are non-interactive. They do not claim exact geographic placement. Only registered recorded services and the existing landmark/area actions produce controls. The player marker indicates that the player is at this site; the game does not track an exact local tile.

## Privacy and optional-data behavior

When the current site is not surveyed, the scene uses a neutral unknown-terrain palette, omits scenery objects, does not list local service buildings or the local site's saved identifying metadata, and uses a generic player-position label. Until that current site is surveyed, the existing route list keeps valid outgoing actions but suppresses biome-specific route descriptions/icons and unvisited destination biome labels. Known travel actions remain owned by the existing travel handlers.

Missing optional service, biome, and route fields are handled without throwing or mutating the saved world. Map render checks compare the saved world JSON before/after rendering.

## Explicit limitations

The generated world contains one populated 7×7 regional layout. It does not store a surveyed local settlement plan, house/street coordinates, traced roads, building interiors, river crossing coordinates, precise player tile position, or local elevation geometry. The local scene is therefore schematic and illustrative, not a local navigation grid. The module does not add new locations/services/NPCs, new movement, or gameplay simulation.
