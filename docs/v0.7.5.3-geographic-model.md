# Infinite Realms v0.7.5.3 — Geographic Hierarchy and Connections

## Status

Additive geographic relationship model built on accepted v0.7.5.2. The existing generated world remains one seeded 7×7 region with 49 site records. No continent/country content, new map, political ownership, biome gameplay, or travel-generation changes are introduced.

## Authoritative entities and sources

| Concept | Authoritative source | v0.7.5.3 relationship | Notes |
|---|---|---|---|
| World | `state.world` / generated world object | `world.id` is the v0.7.5.2 stable ID | `world.seed` remains the generator input; display text is not identity. |
| Continent | `world.continents` | Empty collection until real continent content is implemented | Reserved for future expansion; no continent is fabricated. |
| Country | `world.countries` | Empty collection until real country content is implemented | No borders, ownership, ruler, or faction behavior. |
| Region | `world.region` | `region.id`; optional nullable `continentId` and `countryId` | The existing region object is authoritative; no duplicate region object is created. |
| Site / local location | `world.region.sites[]` | Stable `geoId`, `regionId`; optional nullable `continentId` / `countryId` references | The site record remains the single source for its display name, coordinates, biome, risk, discovery, services, and current gameplay data. It may represent a settlement, wilderness, or landmark. |
| Biome | `site.biomeId`, resolved against `IR_BIOMES` | `world.geography.biomeIds` is a reference-only list of biome keys actually present | The `biome` display label is not copied into a second registry. No biome effects are added. |
| Settlement | Existing site where `site.type === 'settlement'` | `site.settlementId`; `world.geography.settlementRefs[]` stores only `{id, siteGeoId}` | Name, biome, position, services and risk remain on the authoritative site record. A settlement is not duplicated as a second named/location object. |
| Local point of interest | Existing site where `site.type === 'landmark'` | `site.pointOfInterestId`; `world.geography.pointOfInterestRefs[]` stores only `{id, siteGeoId}` | The existing landmark site is the POI for now. This does not add a new local map or invent sub-location content. |
| Travel connection | `world.region.routes[]` | Stable v0.7.5.2 route `geoId`, `fromGeoId`, `toGeoId`; `directed` defaults to `false` for current generated roads | Existing route data and local `site.routes[]` remain authoritative for travel. `world.geography.connectionRefs[]` contains IDs only. |

## Relationships

- World owns the existing primary region and reserves `continents` and `countries` arrays for future real entities.
- Region optionally references a continent and/or country using nullable stable IDs. The current generated region has neither assigned.
- Every current site references its region with `regionId`. Optional `continentId` and `countryId` are nullable and must resolve if populated.
- Settlement and landmark identity are annotations on the existing site record, not duplicate geographic objects.
- Biome is an attribute/classification of a site. A biome may appear in many sites and regions; it is not treated as a parent entity.
- A travel connection links two sites and is not a settlement or parent. Current generated connections are undirected. A future explicit `directed: true` connection is preserved as directional.
- Wilderness/uninhabited sites are valid and do not require a settlement or POI parent.
- A location may have zero outgoing local routes; the validator does not require every site to be connected.

## Integrity validation

`irValidateGeographicHierarchy(world)` is non-destructive. It reports duplicate entity/connection IDs, unresolved parent references, duplicate endpoint pairs, self-connections, unresolved/ambiguous global and local route endpoints, invalid current/known/visited site references, and circular parent chains. It does not delete, rename, re-parent, or choose between ambiguous entities. Discovery and rumor references are warnings when their legacy site IDs do not resolve.

`irEnsureGeographicHierarchy(world)` is idempotent and adds only IDs/references/metadata. It calls the v0.7.5.2 stable-ID layer first. Reference indexes are rebuilt from authoritative records, not separately saved as competing location data.

## Compatibility

- `world.siteId`, `world.known`, `world.visited`, `site.id`, local `route.to`, and global numeric `route.a` / `route.b` remain intact.
- Existing route distance, terrain, caravan/boat flags, shortcut metadata, discovery rules, and travel logic are not changed.
- Existing normalization still rebuilds the seeded world and overlays the current allowlisted saved fields; v0.7.5.3 does not broaden that allowlist or change save schema version.
- No UI/map changes are part of this version.

## Known limitations

1. The current model contains one primary region. Continent and country collections are intentionally empty; no larger world content is generated.
2. Local travel still uses legacy `site.id` / `route.to`, while global map route resolution uses the v0.7.5.2 stable endpoint adapter.
3. The current save normalizer reconstructs the seeded world. This patch ensures geographic metadata is regenerated deterministically during normalization; it does not introduce arbitrary multi-region persistence.
4. Automated JSON and normalization tests do not substitute for a full interactive browser session. Any browser startup limitation is recorded in the test report.
