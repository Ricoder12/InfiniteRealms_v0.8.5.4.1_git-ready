# Infinite Realms v0.7.5.5 — Geographic Data-Integrity Report

## Results

**Generated-world integrity: PASS for the tested seeds.** The v0.7.5.4 suite generated 24 combinations (six seeds × four starting circumstances); v0.7.5.5 added eight further seed/start combinations. The checks assert 49 sites, unique legacy and geographic site IDs, valid geographic hierarchy/indexes, valid biome references, route endpoint resolution, and full route-graph connectivity. Gameplay snapshots are compared against the v0.7.5.3 generator for the same seeds.

**Reference-index consistency: PASS for generated fixtures.** `settlementRefs`, `pointOfInterestRefs`, and `biomeIds` are generated as indexes over the authoritative site collection and are checked for exact match. Repeated index enrichment did not add sites, routes, settlement refs, or POI refs in the existing v0.7.5.3/v0.7.5.4 suites.

**Malformed-fixture handling: PASS for covered cases.** The test suite injects duplicate legacy site IDs, invalid stable route endpoints, stale local stable-route destinations, an invalid current pointer, a dangling journal location, invalid biome IDs, and intentionally mismatched settlement/POI indexes. The validator flags integrity faults without mutating the source world. Where safe to repair, the compatibility wrapper uses only an unambiguous existing relation; otherwise it preserves a notice and rejects map reuse rather than choosing a seemingly convenient destination.

## Fault cases and disposition

- **Missing geographic IDs:** added from existing world seed and legacy site identity; original legacy site IDs are retained.
- **Missing or dangling `site.regionId`:** repaired to the primary region that already contains that site. No country/continent is guessed.
- **Missing or stale local `toGeoId`:** repaired only when the existing travel field `route.to` identifies exactly one site.
- **Missing global connection endpoint:** only filled when the remaining stable endpoint and existing numeric legacy pair make the missing side unambiguous. Otherwise the route is not guessed.
- **Invalid global stable endpoint / duplicate legacy site IDs:** saved-world reuse is rejected; deterministic fallback applies. A compatibility notice identifies that the old world was not safely reusable.
- **Corrupt current `world.siteId`:** use the most recent valid visited site if the saved history proves it; if not, do not silently select another site from the same map. The existing seeded fallback is used and reported.
- **Dangling discovery `siteId`:** source value retained as `unresolvedSiteId`; it is not reassigned to the current location.
- **Invalid biome or mismatched index:** validator reports an integrity error. The existing biome itself is not guessed or overwritten.
- **Dangling NPC site assignment:** reported as warning; no arbitrary NPC relocation is attempted.

## Scope note

This is a report of tests and fixtures actually run, not a claim that every player save or every world extension has been seen. In particular, a user-provided exported save file was unavailable for direct testing. Browser-local persistent storage is separately BLOCKED as described in the test report.
