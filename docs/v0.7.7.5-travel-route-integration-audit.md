# Infinite Realms v0.7.7.5 — Travel and Route Integration Audit

## Starting baseline

Accepted v0.7.7.4 standalone: `backups/InfiniteRealms_v0.7.7.4_accepted_baseline.html` (SHA-256 `8b391d0aac6b22d7dc7109354ff4990efd721c6a15bf31b9fedbac78cc43be8c`). The implementation was compared with the direct-travel function already present in v0.7.7.4 and preserves it as `ir051TravelBase`.

## Existing model and issue

The world stores canonical graph edges in `world.region.routes`. Each undirected edge is also represented as an outgoing `site.routes[]` record at each endpoint for compatibility. Previously, path checks and direct route lookup could trust a local record first or infer a reverse edge without proving that a matching, consistent canonical edge existed. A visible destination could therefore appear reachable even when its authoritative graph edge was missing or conflicted.

The new `js/game/47-travel-route-integration-v0.7.7.5.js` makes `world.region.routes` authoritative. It resolves stable endpoint identifiers where available, rejects missing or ambiguous endpoints, duplicate canonical edges, contradictory distance/transport/terrain metadata, broken mirrored route records, and invalid direction. Local route records corroborate the global edge; they do not independently create a route. Existing state shape is unchanged.

## Source integration

- `irRouteBetween`, map-facing route checks, local exit lists, and travel pathfinding resolve through the same validated connection accessor.
- Multi-leg route planning uses breadth-first search over verified connections, choosing the fewest legs; when multiple adjacent links are explored, the connection list is ordered by recorded distance. It is deliberately not a new shortest-distance/alternative-route planner.
- Each multi-leg execution revalidates the exact planned edge before committing that leg. Direct travel recomputes the quote and verifies the edge immediately before invoking the accepted v0.7.7.4 direct-travel implementation.
- A direct-travel exception restores the pre-trip state snapshot. A multi-leg interruption retains completed legs and does not charge for the next failed/unavailable leg. Each arrival updates the current site, travel count, discovery, events, and save using existing game flows.
- No new route registry or saved fields are introduced. No map pixel coordinate is treated as a gameplay distance.

## Distance, time, energy, fare, and risk

Distances come from recorded `distanceKm`. Existing direct travel duration logic remains in place: foot `ceil(km/20)`, mount `ceil(km/42)`, caravan `ceil(km/30)`, boat `ceil(km/34)`, with a minimum of one day. Base energy follows the existing quote formula (`max(4, ceil(days * 3 + 2)` for foot; the existing direct quote supplies transport-specific values). Existing fares, transport prerequisites, and transport modifiers were not redefined.

Multi-leg journeys continue to use the existing on-foot route mode: each leg uses `irCurrentTransportDays(distance, 'foot')` and the same existing on-foot base energy formula for estimate and execution. A displayed aggregate matches uninterrupted base travel; environmental strain, hunger, events, and encounters can interrupt later legs under established mechanics.

The data currently has no reliable per-edge danger field. Risk uses the existing endpoint location-risk values averaged together, then the existing transport multipliers: caravan 0.72, mount 0.82, boat 0.9, foot 1.0, clamped to 4–48%. An exact percentage or aggregate multi-leg estimate is hidden until all locations needed for that estimate have been surveyed. It is not a safety guarantee. Current-site hazard warnings remain visible because the player is physically there; warning details for unsurveyed future endpoints are withheld to avoid revealing hidden biome information.

Route `terrain` metadata is descriptive only. It does not currently define a supported travel-time speed modifier, so this version intentionally does not invent one.

## World-data snapshot used for browser validation

The deterministic browser test world had 49 sites, 95 canonical global edges, 190 mirrored local route records, and 4 verified exits from the starting location. These counts depend on the generated seed and are not hard-coded by the travel layer.

## Limits and intentional variance

- Multi-leg path planning chooses a route with fewest legs, not necessarily minimum total kilometres, and displays one itinerary.
- Multi-leg journey mode remains on foot; no new mixed-transport planner was introduced.
- Recorded edge distances are used as stored; no missing distances are inferred from screen coordinates.
- Exact timing/base energy agrees with the estimate for uninterrupted travel. Existing environmental hazards, daily effects, events, encounters, hunger/energy constraints, and explicit interruptions may add strain or pause a journey; the preview describes this.
- Save-slot round-trip was tested, but a real player-exported save was not independently tested.
