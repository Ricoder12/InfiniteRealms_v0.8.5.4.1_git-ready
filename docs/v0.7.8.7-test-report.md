# Infinite Realms v0.7.8.7 — Test Report

## Result

The v0.7.8.7 candidate is built and the recorded automated checks passed. It is accepted as the v0.7.8.7 baseline for subsequent work after these checks. The source starting point was the available v0.7.8.6 standalone candidate; the prior v0.7.8.6 release report had not marked that build fully accepted, so this baseline discrepancy remains recorded rather than being silently treated as resolved.

## Main behavior verified

- Political map information uses existing political entity, geographic region, site and NPC/capital references.
- Explicit unclaimed status is shown only when the region carries explicit unclaimed metadata. Missing ownership is shown as unknown.
- Discovered-information rules are preserved; undiscovered capital names are not shown in test cases.
- The current map data lacks real political boundary polygons, so no fabricated border geometry is drawn. The atlas fallback now says boundary geometry is unavailable instead of implying political entities are absent.
- Political panels contain no travel/action buttons. Selecting political information did not change current location, time, energy, or travel count.
- Existing route preview and confirm-travel flow continued to work.
- New seeded worlds create three validated political entities across metadata-only subregions. Five seeds passed uniqueness, capital validity, hierarchy validation, political validation, and same-world physical-geography comparison.
- Repeating an identical seed yielded the same polities and region assignments.
- A generated world save/reload retained the political entity records and region assignments.
- The actual generated-world screenshot shows a new seeded polity in the known area; additional political names are not surfaced until the corresponding regions/locations satisfy discovery rules.
- Legacy saves generated using the accepted v0.7.6.6 and v0.7.7.7 game builds loaded and continued; the v0.7.6.6 legacy initialization retained its root-region assignments and received a conservative polity initialization rather than being repartitioned.

## Key data invariants

For the five tested seeds (`ALPHA-0787`, `BETA-0787`, `GAMMA-0787`, `IR-0787-POLITICAL-MAP-SEED`, `NORTH-MARCH-0787`):
- Three political entities generated per tested fresh world.
- Stable unique polity IDs.
- Valid geography and political validators.
- Capitals, where assigned, resolve to existing settlement sites assigned to the owning region.
- Site IDs, `geoId`s, coordinates, row/column, biome/type fields, per-site routes, and global route records compare unchanged against the physical-only generation output.
- Same-seed rerun reproduces polity records and `regionId` assignments.

## Limitations

- No user-exported save was supplied; compatibility tests used saves generated from accepted older builds and deterministic exploration fixtures.
- The political generator's territorial partition is currently metadata-only. The UI does not draw political boundary lines because the existing model does not yet provide boundary polygons.
- A previous combined browser-test command stalled; relevant suites were rerun in isolation and passed.
- The v0.7.8.6 starting artifact was a candidate with unresolved checks in its previous report; it has not been retroactively marked accepted.
