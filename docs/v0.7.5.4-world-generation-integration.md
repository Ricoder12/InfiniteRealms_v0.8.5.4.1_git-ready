# Infinite Realms v0.7.5.4 — World Generation Integration

## Scope and behavior

v0.7.5.4 is a narrow integration layer over the accepted v0.7.5.3 geographic model. The seeded 7×7 generator remains the source of new world layout, and v0.7.5.2/0.7.5.3 remain the source of stable identifiers and geographic relationships. The new integration does not alter generation algorithms, the map's 49 sites, biome distribution, route generation, route distances, settlement placement, encounter balance, NPC rules, gathering, or local discovery behavior.

The new module is `js/game/35-world-generation-integration-v0.7.5.4.js`. It:

- Runs the existing stable-ID and geographic-hierarchy enrichment for generated worlds.
- Adds `world.generationIntegrationVersion = 1` as a simple schema-integration marker.
- Validates generated and normalized geographic records without deleting entities or changing map layout.
- Uses a narrowly gated saved-world reuse path during `normalizeSave()`. When a version-2 world has a structurally valid site list, route graph, and current location, its saved region is cloned and reused as the normalizer's working world. That preserves saved location labels, route metadata, site-local persistent fields, saved world extensions, and NPC schedule data instead of replacing the region with a newly generated map merely because geography fields were added.
- Enriches pre-geography version-2 saves with stable fields in place, while retaining legacy `site.id`, numeric global `a`/`b`, and local `route.to` compatibility.
- Retains the existing fallback normalization path for malformed or older saves that do not meet the reuse gate. Such maps are still normalized using the prior seed-based compatibility behavior.

This adapter is synchronous and only scopes the saved-world reuse to the generator call made from its paired `normalizeSave()` call. Normal new-world generation continues through the v0.7.5.3 generator.

## Authoritative data sources

| Entity or property | Authoritative record | Integration behavior |
|---|---|---|
| World identity / seed | `world.id`, `world.seed` | Stable identity and seed input remain separate. |
| Regions | Existing `world.region` object | No second region record is created. |
| Sites, settlements, wilderness, landmarks | `world.region.sites[]` | Each site remains authoritative for its legacy ID, stable geographic ID, name, biome, coordinates, discovery, risk, services, persistent changes, and local routes. |
| Biome | `site.biomeId`, `site.biome` | No biome labels are copied into a second collection; `world.geography.biomeIds` is reference-only. |
| Settlements and local POIs | Existing site record plus `settlementId` / `pointOfInterestId` | Geographic indexes point back to a site's `geoId`; they do not copy names, position, or biome values. |
| Global travel connections | `world.region.routes[]` | Existing endpoint properties and travel metadata are retained; stable `geoId`, `fromGeoId`, and `toGeoId` resolve endpoints. |
| Local travel destinations | `site.routes[]` | Existing `route.to` remains authoritative for gameplay; `toGeoId` is an additive stable reference. |
| Travel/discovery state | `world.siteId`, `world.known`, `world.visited`, `world.journal`, site `discovered` / `changes` | Reused valid v2 saves retain existing state; the normalizer still validates/filter known and visited references. |
| Location-dependent NPC data | Existing `world.v06` / related saved world fields | Preserved as part of the existing world object when a valid save is reused; no extra NPC generation is added by this geographic adapter. |

Continent and country collections remain reserved and empty unless actual records already exist. v0.7.5.4 creates no new continent/country content, borders, ownership, or political simulation.

## Validation and safety behavior

- Generated world IDs, site IDs, route IDs, parent references, and route endpoints are validated after the existing enrichment functions run.
- The save reuse gate rejects duplicate legacy site IDs, unresolved or ambiguous route endpoints, duplicate connection endpoint pairs, invalid local route targets, unresolved parent fields, and a missing current location.
- A malformed map does not get silently repaired by choosing an arbitrary route endpoint; it falls back to the existing normalization path.
- Valid isolated locations remain allowed by the geographic model; the current generated world still has a connected road graph due to the existing grid generator.
- Repeated enrichment rebuilds only reference indexes; it does not append duplicate sites, routes, or NPCs.

## Generation compatibility

For identical seed/circumstance combinations, tests compare the final v0.7.5.4 generated-world gameplay snapshot with the v0.7.5.3 generator's output. The snapshot includes site names, coordinates, biomes, settlement type/services, risk, local routes, global travel properties, current/known/visited locations, and journal values. Only the v0.7.5.4 integration marker is new.

## Limitations

- This model remains one 49-site region. Continents/countries, additional regions, and cross-region travel are not implemented.
- There is no new map visualization or biome gameplay.
- Browser UI startup and a real browser localStorage session must still be manually checked; automated integration tests use Node's VM with a minimal DOM shim and production `normalizeSave()` but do not constitute a full interactive browser run.
- Invalid/malformed and pre-v2 saves that cannot pass the reuse gate retain the earlier fallback migration behavior; this patch does not promise lossless preservation of arbitrarily malformed save data.
