# Infinite Realms v0.7.8.2 — Test Report

## Starting point

The v0.7.8.1 milestone was an audit, not a new playable binary. The actual accepted starting build is v0.7.7.9. The extracted source archive's `dist/infinite-realms.html` and the accepted v0.7.7.9 standalone matched byte-for-byte before editing.

## Focused political entity suite

Covers empty registry defaults, stable ID generation, all five supported entity types, missing optional fields, settlement capital references, duplicate IDs, unsupported `unclaimed-region` type, invalid region and capital references, missing geographic anchors, invalid governing references, mixed-type governance, circular/self governance, geographic generation equivalence apart from the empty registry, no duplicated sites/routes/geography, legacy save normalization, repeat-safe normalization, and malformed registry defaults.

## Chromium browser suite

`tests/v0.7.8.2-political-entity-browser.py`: 24/24 passed.

Real Chromium run confirmed:
- A save generated by the accepted v0.7.6.6 game code loads and gets an empty registry.
- A save generated by accepted v0.7.7.7 loads with character progression and geography intact.
- Current version title is v0.7.8.2.
- Entity records validate in-browser, including optional fields, duplicate IDs, invalid references, and save normalization.
- Creating a test polity on a copied world does not change the authoritative site/route/geography objects.
- World/Regional/Local switching is non-mutating.
- Extensive-exploration state, visits/discoveries, gear, inventory, NPCs, relationships and reputation survive loading; travel/reload continue to work.
- No uncaught browser errors were recorded.

The old-save and extensive-exploration data were generated from accepted baseline code during the test; no personal user-exported save was provided.

Historical tests were updated where they asserted a prior current-release title/order or compared generated JSON byte-for-byte with a pre-political version. Those generation comparisons now ignore only the new empty `world.polities` property while still requiring all existing generated data to match exactly.

## Known limitations

- No political entities are seeded; `world.polities` remains empty in generated worlds unless future code explicitly adds records.
- The live geography model currently has one authoritative `world.region` object. `regionIds` validates against that existing region; it does not add multi-region geography.
- `world.countries[]` remains the existing geographic hierarchy registry and is distinct from political `world.polities[]`; the relation between geographic country records and political country entities is not established in this version.
- “Unclaimed” is intentionally not an entity type. Territorial status and regional ownership remain future work.
- No user-exported save was tested; compatibility was verified with saves produced by accepted builds and a deterministic exploration fixture.
- Browser screenshots document legacy-save Character/map smoke only; the version adds no political UI.

## Result

The data foundation is complete for v0.7.8.2. No regional ownership or political simulation was started.
