# Infinite Realms v0.8.2.4 — Guild Contract Board and Acceptance

## Starting point and implementation decision

Started from the accepted v0.8.2.3 source. The v0.8.2.1 audit was reviewed at `docs/v0.8.2.1-guild-services-audit.md` (included in the source archive). It found that `JOBS`/`IR_LIFE_JOBS` are employment records and that the legacy faction contract handler immediately advances time, pays a reward, and changes standing. Neither system represents a guild-specific offer or safe acceptance lifecycle. Guild organization records from v0.8.1 and the shared membership state from v0.8.0 were reused; a small guild-offer registry and acceptance-only state were added because no existing contract registry could support this scope safely.

## Behavior

Each valid Adventurers’ Guild organization exposes three stable, guild-scoped offers. The board shows title, description, category, membership requirement, objective description, and available/accepted state. An offer from one organization is not treated as belonging to another. Players can inspect offers without membership, but must have active Adventurers’ Guild membership to accept. Existing NPC presence, combat, and event guards still apply.

Accepted contract state is stored on the character as `guildContractState: { schema: 1, accepted: [...] }`. Each accepted record retains the stable contract ID, guild ID, accepted status, and acceptance date. The board shows accepted offers as active and blocks repeat acceptance. There is no objective progress, completion action, reward, time advance, item change, standing change, public reputation change, or rank progression in v0.8.2.4. Offers have no expiration or custom guild-specific requirements because the current data model does not support them. No reward preview is shown because these new offers do not have validated reward definitions.

## Existing systems and boundaries

The standard job board remains employment-only and its employment records and hiring function are unchanged. The old faction-contract action remains unchanged; it resolves immediately and is therefore not used for the new board. Acceptance creates a guild contract record only. Completion, objective tracking, rewards, duties, and adventurer ranks remain for v0.8.3.

## Known limitations and save compatibility

- All guilds share the existing Adventurers’ Guild faction membership. Per-guild eligibility and application/approval data do not exist.
- Offers are deterministic templates instantiated against the stable organization ID. Offer expiration, structured objective validation, and reward definitions are not supported.
- Existing saves without `guildContractState` remain without that optional field until an offer is accepted. Contract state survives the tested production save/load normalization path.
- Browser behavior and user-exported save compatibility were not manually tested.

## Rollback

Restore the accepted v0.8.2.3 source ZIP and standalone HTML. The v0.8.2.3 package remains unchanged. The new contract state is additive: the base save version and existing fields remain unchanged, and the optional namespaced character field appears only after acceptance.
