# v0.7.7.8 Save and Data Ownership Audit

## Authoritative data
- **World / regional / local maps:** use existing `state.world.region.sites` and `state.world.region.routes`; each site retains its stored `id` and optional `geoId`. `state.world.siteId` remains the current location. `known`, `visited`, site discovery state, journal records, and routes remain saved game data.
- **Travel:** uses the established travel integration. The browser test verified that a valid travel operation changes current location and increments travel count once without adding a location or global route record.
- **Character status:** reads `state.character` values and existing item/equipment data rather than creating a parallel stat, skill, inventory, or equipment source.
- **Map selection:** scope, selected geographic ID, and intelligence-origin indicator are transient UI state and reset when the top-level state object changes.
- **Lead subsystem:** existing `world.v0723` data is preserved and initialized ahead of first render only if missing or structurally invalid, preventing a display-only map render from adding a late default.

## Integrity audit
`ir0778AuditSaveWorld` reports duplicate site IDs, duplicate geographic IDs, duplicate global route IDs, an unresolved current location, and unresolved known/visited references. It is diagnostic and does not mutate the passed world.
