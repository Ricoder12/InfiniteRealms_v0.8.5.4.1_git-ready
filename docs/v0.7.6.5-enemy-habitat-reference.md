# Infinite Realms v0.7.6.5 — Enemy Habitat Reference

## Rules at a glance

This version adds runtime habitat profiles for the 16 established enemy definitions. Normal encounters use the current site's canonical `IR_BIOMES` ID and the existing `IR_BIOME_ENEMIES` candidate pool. The pool's order and repeated entries are preserved; candidates that conflict with habitat metadata are removed. The runtime profile is in `js/game/41-monster-habitats-v0.7.6.5.js`.

A `cave` label remains a legacy label handled by the existing biome resolver; there is no new `cave` entry in `IR_BIOMES`. Dungeon encounters continue to use the explicit dungeon-stage rules. The Dragon carries a Mountain lore habitat while remaining explicitly ineligible for ordinary random encounters; `volcano` remains legacy lore metadata and is not a currently supported biome ID.

## Reconciled data conflicts

The former Desert pool included Slime even though the enemy's own habitat data described swamp, cave, river, and coast. Slime is now removed from Desert, while Bandit, Thief, and Boar remain valid options. Thief and Boar gain Desert in their runtime habitat metadata, consistent with the established pool's caravan / dryland-fringe intent. The River pool previously contained Wolf and Spider while their per-enemy metadata omitted River; both profiles now acknowledge river-bank terrain.

The baseline's other per-biome candidate lists are retained. The module does not copy enemy records, add species, or change HP, attack, defense, XP, level, loot tables, or coin ranges.

## Uncontrolled encounter safeguards

The existing local-risk thresholds are retained: the random selector still adds its existing higher-danger candidates only above risk 27 / 38. In addition, habitat-filtered *uncontrolled* random encounters use conservative safety gates:

- Threat rank 3: local risk at least 28 and Combat skill level at least `max(3, enemy level − 5)`.
- Threat rank 4 or higher: local risk at least 38 and Combat skill level at least `max(8, enemy level − 5)`.

These gates only affect uncontrolled/random selection and scouting ambush pools. A deliberate hunt still uses the existing hunt choices; explicitly scripted combat, sparring, settlement incidents, and dungeon-stage bosses bypass biome-random filtering and keep their original rules. Combat scaling and reward calculations are not changed.

## Compatibility

Habitat data is runtime configuration, not character/world save state. Existing saved characters, active-combat payloads, inventory rewards, dungeon state, and save-schema version are not migrated by this feature.
