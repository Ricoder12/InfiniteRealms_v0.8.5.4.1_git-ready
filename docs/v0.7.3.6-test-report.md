The patch is packaged as a release candidate, but the browser checklist remains required before calling all completion criteria satisfied.

## Changes in v0.7.3.6

- Added `js/game/32-feedback-antifarming-regression-v0.7.3.6.js`; it is loaded immediately before `27-boot.js`.
- Wrapped existing relationship-changing callbacks to capture their before/after affinity, trust, and public reputation; emits one concise notification with actual deltas rather than contradictory separate generic toasts.
- Keeps personal relationship changes explicitly separate from public reputation. Important existing benefit feedback (e.g. wages, skills, discounts) is retained when the relationship message is consolidated.
- Caps positive relationship gains by NPC and interaction category, so repeated talk/favor/time/meal/task/work/training/social activities cannot provide unlimited affinity/trust. Distinct activity categories retain their own reward allowance.
- Limits gift-based relationship rewards to one per NPC for each gift-item type, while retaining the existing three-day gift cooldown and existing reputation/trait modifiers.
- Deduplicates callbacks for the same NPC/action within 450 ms in the current page session. Prevents repeated reward from the same persistent guard disturbance.
- Corrects only the just-created conversation memory's stated relationship delta when the actual gain was capped; historical memory entries are not rewritten.
- Persists earned relationship caps after the interaction's own save call so closing immediately after the action cannot discard the cap. Valid old cap and gift-claim entries are retained rather than truncated.
- Keeps existing payment, skill practice, item, discount, combat, occupation and save schema logic. `saveSchemaVersion` remains 8.

## Known issues and remaining verification

1. **Live browser verification is outstanding.** The available Chromium process hangs even on a blank page; new-game, real save/load, normal UI interactions, and live travel cannot be marked PASS. This release does not yet meet the user's full end-to-end completion criterion.
2. **Lifetime caps are intentionally strict.** Once the configured per-NPC/action allowance is spent, that same interaction can still grant its ordinary non-relationship benefits, but it cannot keep increasing affinity/trust. Different meaningful action types have separate allowances.
3. **The `world.v0736` anti-farming ledger retains valid historical keys.** This prevents old NPC reward caps from being forgotten and farmed again; save size therefore grows gradually with unique NPC/action and gift records.
4. **The 450 ms duplicate-callback guard is session-local.** Persistent caps and existing event ledgers protect tracked rewards across saves; the short debounce itself resets on page reload.
5. **Existing memory retention limits remain.** The earlier memory layer retains at most five active memories per NPC and the existing journal cap. v0.7.3.6 does not redesign that storage.

## Failures found and corrected during implementation

- The first failed-action test found that an empty earned-ledger row could be created even if the interaction failed for insufficient energy. Fixed so only an actual positive relationship gain creates an earned entry; rerun passed.
- A persistence test showed the original callback saved before the anti-farming counter had been written. Fixed by persisting the updated ledger after the action completes; the saved-ledger test now passes.
- Review found old ledger truncation could discard a cap after many more NPC entries. Removed eviction of valid historical earned/claim entries and added a regression test; it passes.
- Test-harness assertions/setup were corrected during development; the final six suite runs pass. The remaining browser smoke failure is the environment-level Chromium hang described above and cannot be validated as an in-game failure or success.

## Rollback instructions by patch

These scripts are layered wrappers and must stay in the listed load order. To roll back a patch from the current v0.7.3.6 source tree, remove that patch's `<script>` tag from `index.html`, remove the matching module file, set the title/version back to the target version, then run `node build.js`. **When rolling back an earlier version, also remove every later wrapper layer**, because later modules may call or wrap earlier APIs. For the safest rollback, open the matching untouched standalone backup instead of hand-editing shared script order.
