# Infinite Realms v0.7.3.5 — Contextual Favors and Information

## Summary

This patch introduces contextual decision logic for selected existing favors and information interactions. It reuses `n.memories`, existing affinity/trust/status values, public `character.reputation`, and the existing event/journal records. It does not create new memories for past events, rewrite the memory storage implementation, add a relationship/reputation meter, or change save schema 8.

The patch is isolated in `js/game/31-contextual-favors-information-v0.7.3.5.js`, loaded immediately before `27-boot.js`.

## Contextual rules

- **Favors:** A meaningful helpful memory stored on the specific NPC can add +2 to one favor attempt. The memory is then marked as used for the favor context so the same record cannot repeatedly improve future attempts. The normal affinity/trust requirement, energy cost, three-day cooldown, reputation modifiers, trait modifiers, reward, and trust gain are retained.
- **Broken promises and harm:** A recorded broken promise adds a -5 favor-score modifier; other unresolved personal harm adds -4. When an NPC is the player's enemy, or serious remembered harm coincides with negative trust, that NPC can refuse the favor before spending energy. These effects only examine the target NPC's personal record. A more recent reconciliation recognized by the existing memory logic can clear the grievance.
- **Guard information:** Guards always provide basic local risk/terrain information. Specific active-event details are shared only when personal trust, positive public standing, or a relevant unused helpful memory supports it. An unresolved grievance keeps details general.
- **Hunter information:** The basic biome-based huntable-sign list remains available. A specific existing biome clue is disclosed when contextual information rules permit it. A relevant positive cooperation memory can improve one targeted hunt lead by +1 quality once; the existing hunt system still determines encounters and outcomes.
- **Scholar information:** Existing record titles remain available. Extra explanation is taken only from actual `journal.discoveries` or `world.v05.history` details, and requires suitable context. No lore is fabricated.
- **Innkeeper rumors:** Existing unresolved rumors remain the source of all rumor details. An innkeeper can withhold optional information when a personal grievance remains, or when low public reputation and low trust coincide. A relevant helpful memory can override the latter once; the same record cannot be reused to override the gate repeatedly.
- **Public vs. personal:** Public reputation affects general willingness, but does not erase a target NPC's recorded grievance. Memory use is keyed by NPC, topic, and a stable fingerprint of the existing record. Existing memory entries themselves are not edited or deleted.

## Affected functions/files

Only these project files changed for gameplay:

- `index.html`: title/version updated and the new patch script added after v0.7.3.4.
- `js/game/31-contextual-favors-information-v0.7.3.5.js`: new module wrapping `ir06Favor`, selected `ir072Action` info handlers, `ir0724TrackTarget`, `persist`, `normalizeSave`, `shell`, and `topbar`.

Underlying memory storage, NPC generation, occupations, schedules, combat, jobs, prices, and reputation reward functions were not edited. Existing actions retain the normal occupancy/presence/combat checks and occupation-specific checks.

## Known limitations / untested behavior

- Browser end-to-end testing could not be completed in the current environment. Manual in-game verification remains outstanding.
- A promise-related reaction occurs only if the existing NPC memory record explicitly captures a broken/kept promise. This patch does not invent a promise system or fabricate a promise history.
- Contextual help recognition intentionally relies on explicit content in the target NPC's memory text/kind. An old save with vague/ambiguous memories will not be treated as proof of help.
- The patch uses existing relationship statuses and `n.memories`; it does not propagate one NPC's private memory to others or create public knowledge from private events.
- The detailed information path reads existing regional-event, biome-enemy, discovery, and history records. It does not create new quests, rumors, enemy types, or world events.

## Rollback

The untouched standalone baseline is `backups/InfiniteRealms_v0.7.3.4_backup.html`, also delivered separately as `InfiniteRealms_v0.7.3.4_backup.html`.

To disable only v0.7.3.5 in the source project:

1. Remove `<script src="js/game/31-contextual-favors-information-v0.7.3.5.js"></script>` from `index.html`.
2. Delete `js/game/31-contextual-favors-information-v0.7.3.5.js`.
3. Restore the title/version in `index.html` to v0.7.3.4.
4. Run `node build.js` to rebuild the previous source project, or open the untouched v0.7.3.4 standalone backup.

The new context-use ledger is an additive `world.v0735` property. The v0.7.3.4 baseline ignores it if you use the original backup; no underlying memory records were rewritten by this patch.
