# Infinite Realms v0.7.8.2 — Change Log

## Implemented

1. Added `js/game/52-political-entity-foundation-v0.7.8.2.js`, defining one `world.polities[]` political identity registry and five supported entity types: `country`, `kingdom`, `empire`, `city-state`, `tribal-territory`.
2. Added deterministic IDs derived from the existing stable world ID plus a caller-provided logical key. No generated entities use display names, array position, or random IDs.
3. Added a minimal record factory with required ID/name/type and optional description, region references, capital-site reference, and governing entity reference.
4. Added non-mutating validation for duplicate IDs, supported types, valid geographic region references, existing settlement capitals, governing references, self-governance, and circular governing chains.
5. Added an empty `world.polities` registry for new worlds and safe defaults for older saves that do not have the optional property. Valid existing polity arrays and their records are preserved.
6. Updated version branding/load order in `index.html`; the module runs after v0.7.7.9 acceptance and before application boot.
7. Added focused Node and Chromium tests and adjusted historical current-release assertions / generation-equivalence checks to recognize the current title and the one intentionally additive empty registry.

## Not changed

- No political data is seeded in generated worlds; the default polity registry is empty.
- `world.region`, site records, route records, geographic IDs, coordinates, biomes, discovery, and travel logic remain authoritative and unchanged.
- No `status` field or territorial ownership model is added. `unclaimed` is not a polity type and is deferred to the future territorial-status layer.
- No diplomacy, factions, player allegiance, guild ranks, wars, conquest, government/ruler generation, UI, save-schema version, or gameplay mechanics are changed.
