# Infinite Realms v0.7.3.3 — Reputation-Based NPC Reactions

## Scope

Added the isolated layer `js/game/29-reputation-based-npc-reactions-v0.7.3.3.js` after the v0.7.3.2 witness-based reputation patch and before boot. The previous patch files and the baseline standalone HTML were not edited.

## Changes and affected functions

- `ir072RequireNPC`: restores the original presence/combat validation so low public reputation no longer prevents opening the NPC interaction screen or accessing every occupation service. Social interaction handlers retain their own low-reputation checks.
- `ir072InteractionModal`: uses the existing occupation modal and appends a reputation explanation plus the NPC-specific remembered-history line. The blanket refusal overlay is no longer used for every interaction.
- `ir073MemoryStanding` and `ir073ContextLine`: give a specific NPC's recorded harm or active Enemy relationship priority over unrelated newer gifts/help when evaluating the NPC's response. An explicit newer reconciliation memory can soften the active grievance; memories are not deleted.
- `ir072Bargain`: preserves the current costs, daily attempt limit, one-purchase coupon, and existing 8%/12%/15% discount tiers. Low public reputation can refuse the optional negotiation. A personal grievance prevents public reputation from raising the discount tier, improving the success chance, or adding the existing trust bonus.
- `ir072ShopCard`: explains when a personal grievance prevents a high-reputation bonus.
- `ir04ItemPrice`: retains the existing price formula but guards the final result as a finite integer of at least one coin.
- `shell`, `topbar`, `persist`, `normalizeSave`: update display/save metadata to v0.7.3.3 while retaining save schema 8.

No existing occupation handler, combat function, loot handler, reputation meter, or save schema definition was rewritten.

## Known limitations

- Witness and public knowledge logic remains governed by v0.7.3.2; this patch does not add new reputation sources or a reporting UI.
- Public reputation continues to influence existing talk/favor outcomes. A grievance is surfaced in the interaction context and suppresses the reputation-based merchant bonus, but direct player actions like talking or giving a gift can still affect the relationship under the existing rules.
- A newer explicit reconciliation memory can soften the memory-based grievance only while that reconciliation remains in the NPC's retained memory history; longer-term resolution still follows the existing relationship and memory limits.
- Full browser playtesting remains outstanding because Chromium did not return a DOM in this environment.

## Rollback

To revert only v0.7.3.3 in the split source project:

1. Keep `backups/InfiniteRealms_v0.7.3.2_backup.html` untouched.
2. Remove this script tag from `index.html`: `<script src="js/game/29-reputation-based-npc-reactions-v0.7.3.3.js"></script>`.
3. Delete `js/game/29-reputation-based-npc-reactions-v0.7.3.3.js`.
4. Change the `<title>` in `index.html` back to `Infinite Realms — Version 0.7.3.2`.
5. Run `node build.js` to rebuild the v0.7.3.2 source baseline, or use the separately delivered untouched `InfiniteRealms_v0.7.3.2_backup.html`.

Only the new patch file, script tag/title, README, test, and report were added or updated for this release; the v0.7.3.2 baseline was preserved.
