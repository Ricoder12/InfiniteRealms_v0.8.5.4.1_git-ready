# v0.8.3.3 Guild Duty and Personal Progression

## Starting build and approval

This release candidate is based on the user-accepted v0.8.3.2 source archive. The Goblin/Bitterleaf/Field Bandage duty templates, expiry and cancellation rules, credit amount, per-category daily cap, `character.daysLived` reset key, character-owned persistence field, and quarantine recovery were explicitly supplied and approved by the user before implementation.

## Templates and authoritative events

| Duty | Stable template ID | Target | Qualification |
|---|---|---|---|
| Defeat Goblins | `goblin-defeat-3` | `IR_ENEMIES.goblin.id` | Confirmed `irCombatEnd('victory')` against a goblin; sparring is excluded. |
| Gather Bitterleaf | `bitterleaf-gather-5` | `ITEMS.herb` (display name Bitterleaf) | Actual positive `herb` inventory delta from `ir04Gather('herbalism')`. |
| Deliver Field Bandages | `field-bandage-delivery-2` | `ITEMS.bandage` (display name Field Bandage) | Inventory quantity removed at the issuing receptionist and recorded in the same save transaction. Partial deliveries are retained. |

Source IDs and hooks are checked at runtime before templates are enabled. Each character may have at most one active instance of a given template per issuing guild; reacceptance is available after the earlier instance closes. An accepted instance receives a stable sequence ID and begins tracking only after acceptance. Active progress is retained on save. Cancelling is always available at the issuing receptionist; expired and cancelled duties remain in history without credit. The three templates have no inferred failure state.

Each duty expires 14 in-game days after acceptance, keyed to `character.daysLived`. Expiry is applied as soon as time reaches the boundary and before any subsequent qualifying event. Item delivery may be partial and consumes only the quantity accepted by the issuing receptionist.

## Personal progression record

`character.adventurerProgression` owns `schema`, `currentRank`, `dutyCredit`, `activeDuties`, `dutyHistory`, `dailyCredit`, monotonically increasing duty/event sequences, `processedEventIds`, and a pending herbalism event used to recover the narrow interval between output persistence and progress callback. It does not reuse the general XP field `character.progression`, guild membership, standing, or public reputation.

Each completed duty grants one duty credit. Each category has a shared cap of two credits per character per in-game day; the total possible across the three categories is six. A duty completed after its category cap is reached remains completed, records zero duty credit, and is not deferred. Rank is not advanced by credits in this release.

Missing progression data initializes to F rank and empty duty ledgers. Missing fields in a valid progression record receive defaults while unknown fields and valid ranks remain. Invalid or conflicting progression data is left intact, marked quarantined through `character.adventurerProgressionIntegrity`, and disables duty/progression actions. Unsupported records are not repaired or replaced.

## Boundaries

Guild duties remain separate from the existing acceptance-only guild contract board, personal NPC tasks, and general XP progression. No examinations, promotions, demotions, rank-gated contracts, contract completion, or later roadmap features are implemented. Browser UI validation and user-exported save-file testing remain unperformed.
