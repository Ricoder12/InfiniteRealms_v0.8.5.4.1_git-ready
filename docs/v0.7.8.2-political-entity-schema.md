# Infinite Realms v0.7.8.2 — Political Entity Schema

## Scope

This schema establishes political identity records independently from physical geography. It does not generate countries, kingdoms, empires, or any other political content. New worlds start with `world.polities: []`; existing saves that lack the optional collection receive the same empty default during normalization.

## Authoritative data ownership

- `world.region`, `world.region.sites[]`, and `world.region.routes[]` remain the existing geographic/site/connection source of truth.
- `world.continents[]` and `world.countries[]` remain the existing geographic hierarchy registries. `world.geography` remains a derived index, not a second location registry.
- `world.polities[]` is a separate registry for political identities. It does not contain copies of settlement, route, biome, terrain, or discovery records.
- A political `type: 'country'` means a political country/state. It is not a copied record from the geographic `world.countries[]` collection. Connecting the two concepts requires an explicit later schema decision; v0.7.8.2 does not assign political ownership.

## Record contract

Required fields:

| Field | Meaning and validation |
|---|---|
| `id` | Unique, stable string ID. Preferred builder: `irPoliticalEntityId(world.id, stableKey)`. The stable key must be a logical identifier, never a display name, array position, or random value. |
| `name` | Non-empty display name. |
| `type` | One of `country`, `kingdom`, `empire`, `city-state`, or `tribal-territory`. |

Optional fields:

| Field | Meaning and validation |
|---|---|
| `description` | Optional short text description. |
| `regionIds` | Optional array of existing geographic region IDs. In the current architecture, the only live region record is `world.region`; a reference must resolve to that record. |
| `capitalSiteGeoId` | Optional stable geographic site ID of an existing site whose `type` is `settlement`. No settlement is created to fill a missing capital. |
| `governingEntityId` | Optional ID of another polity. It must resolve uniquely, cannot point to the same record, and cannot form a circular governing chain. No type-specific rank order is enforced. |

Each polity must be spatially anchored by at least one valid `regionIds` reference or a valid `capitalSiteGeoId`. Optional description and governing relationship are not required for a minimally valid entity.

There is no `status` field in this release because no lifecycle meaning is required for the entity foundation. “Unclaimed” is not an entity type. Territorial status such as `unclaimed` belongs on a future geographic territorial-status/assignment layer once regional ownership is approved; it is deliberately not persisted in v0.7.8.2.

## APIs

- `IR_POLITICAL_ENTITY_TYPES`: frozen list of supported political entity types.
- `irPoliticalEntityId(worldId, stableKey)`: deterministic world-scoped ID helper.
- `irCreatePoliticalEntityRecord(world, input)`: creates an in-memory record only when explicitly called. It does not insert the record into `world.polities`.
- `irEnsurePoliticalEntityRegistry(world)`: supplies `world.polities: []` if the registry is absent or malformed; it does not rewrite records inside a valid array.
- `irValidatePoliticalEntities(world)`: non-mutating validator for record shape, unique IDs, geographic anchors, settlement capitals, governing references, and circular governing links.

Validation returns `{ ok, errors, warnings, counts }`. Invalid existing records are reported, not automatically removed, renamed, or rewritten.

## Save/load behavior

The wrapper runs after the existing world-generation and save-compatibility layers. Generated worlds receive an empty registry; save normalization adds an empty registry to older worlds only when the property is absent or not an array. Existing arrays are preserved and validated. No save version, geographic ID, site, route, seed, discovery, visit, or character-progress migration is added. No world regeneration is initiated by the political entity module.

## Explicitly out of scope

No seeded political content, regional ownership, country assignment to sites, border geometry, government/ruler/capital generation, player allegiance, faction membership, diplomacy, wars, conquest, political UI, NPC relationship/reputation changes, or travel/combat/biome changes.
