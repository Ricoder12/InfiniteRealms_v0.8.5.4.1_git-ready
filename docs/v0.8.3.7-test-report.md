# Infinite Realms v0.8.3.7 — Test and Release Report

## Result

The branch and quest-board presentation update is implemented in an isolated candidate tree. It is not yet accepted. The working source is based on the verified v0.8.3.6 candidate. The latest explicitly accepted rollback remains v0.8.3.4; its standalone and source ZIP were hash-checked before edits and were not modified.

## Changes

- Association branch cards now group the saved branch name, configured location, receptionist reference, and guildmaster reference. The member's own branch is highlighted; without membership, the branch at the current location is highlighted where a matching branch exists.
- Added branch anchor navigation and separated branch-specific staff from Association-wide leadership. Removed the duplicate branch staff list from the separate leadership panel.
- Branch cards provide direct service links to dedicated contract and duty boards; duplicate inline offer lists were removed. Both boards share responsive quest-card styling. Duty offers identify the objective category, target, quantity, and the existing personal-credit cap. Board cards retain existing objective and completion actions.
- Board headers state the one-active-Association-assignment rule. When an assignment is active, conflicting acceptance buttons are disabled for clarity; the existing v0.8.3.6 acceptance wrappers remain authoritative. Quarantined assignment data also disables new acceptance and displays its reason.
- No new save fields, migrations, quest rules, ranks, rewards, completion logic, or global member registry were added.

## Validation actually executed

- Node test files: **51 passed, 0 failed**. This includes the full existing regression suite, the v0.8.3.3 production-path test with v0.8.3.7 assertions for branch navigation and cross-type quest exclusion, and the new focused board-presentation test.
- JavaScript syntax: **85 passed, 0 failed** using `node --check` for every `.js` file under `js/`.
- Standalone build: **PASS** with `node build.js`.
- Source archive integrity: **PASS**. Extracted the source ZIP, rebuilt the standalone, and confirmed its SHA-256 matched the release HTML byte-for-byte.
- Production-path simulation: **PASS**. The test loaded the source modules in a VM, generated a world, opened the Association tab, followed the saved branch data, opened the duty board, accepted a duty, and verified another duty and a contract were blocked while board controls reflected the active slot.
- Browser interaction and screenshots: **NOT TESTED / NOT CAPTURED**.
- User-exported saves and manual old-save loading: **NOT TESTED**. Existing automated save normalization and compatibility fixtures ran as part of the 51 test files; these are not a substitute for actual exported save files.

## Known limitations

- Branch selection is derived from current authoritative membership or current location. If neither resolves to a registered branch, none is labeled selected.
- The interface still relies on supported current records; it does not fabricate missing staff, locations, rewards, membership, or objective data.
- Contract and duty lifecycle behavior is preserved from v0.8.3.3–v0.8.3.6; this release changes presentation and reinforces UI feedback only.
- Explicit acceptance is pending. Do not treat this candidate as the accepted baseline until reviewed.

## Rollback

Use the unchanged accepted v0.8.3.4 standalone and source archive listed in the output manifest. The v0.8.3.6 candidate also remains preserved unchanged. No user save files were changed.
