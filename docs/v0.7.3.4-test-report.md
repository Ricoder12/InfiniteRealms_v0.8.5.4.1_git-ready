# Infinite Realms v0.7.3.4 — Positive Reputation Sources

## Summary

This patch adds a small integration layer for positive **public** reputation. It reuses `character.reputation` and the existing `ir073ChangeReputation` function; it does not add a second reputation meter. It stores only cooldown/award history in `world.v0734`, and keeps the existing save schema at version 8.

## Supported positive reputation sources

| Activity | Public reputation | Repeat protection | Completion condition |
|---|---:|---|---|
| Paid job shift | +1 | 30 simulated days | `jobShifts` increments and the existing `Shift completed:` feed entry appears |
| Farmer assistance | Existing +1 | 7 simulated days, shared across farmers | Base farmer-work handler passes its energy/hunger/daily checks and actually completes the work |
| Hunting-material sale to a hunter | +1 | 14 simulated days, shared across sales | Existing hunter sale succeeds: eligible inventory decreases, coin increases, and the sale feed entry appears |
| Return lost property | Existing +2 | 30 simulated days | Existing successful return choice |
| Help a courier | Existing +1 or +2 depending on the existing path | 14 simulated days | The existing help choice resolves |
| Give courier directions | Existing +1 | 14 simulated days | The existing advice choice resolves |
| Fair roadside goblin conversation | Existing +1 | 30 simulated days | Only when the existing social check grants its positive reputation |
| Short supply contract | +2 | 14 simulated days | Existing event records delivery completion |
| Mediate a local dispute | Existing skill-scaled +1 or +2 | 21 simulated days | Existing mediation handler completes |
| Repair commission | +1 | 30 simulated days | Existing repair action completes |
| Mark a trail and warn travelers | Existing +1 | 14 simulated days | Existing trail-marking action completes |
| Caravan escort | +2 | 21 simulated days | Existing escort handler records the completed safe arrival |
| Fair salvage sharing | Existing +2 | 21 simulated days | Existing sharing outcome completes |
| Cleanse a shipment from a curse | Existing +1 | 21 simulated days | Existing cleansing job completes |
| Safe material research assistance | +1 | 30 simulated days | Existing research-assistance action completes |

A private hunt by itself does **not** grant public reputation; turning eligible materials in to an existing hunter is the public/community-supply path. Failed or cancelled actions should not receive awards. Cooldown entries are keyed by activity, so repeated trivial completions cannot give unlimited public reputation.

## Existing sources deliberately left intact

- Existing completed bounty: +5 with its active/completed status guard.
- Existing criminal-group threat rewards: +3 / +4 with their existing claim guard.
- Existing daily road-bandit reward: existing day-based guard.
- Existing guard report for recorded criminal activity: +3 and its current one-report guards.

These callbacks were inspected and were not rewritten by this patch. The patch does not award positive reputation for a generic enemy victory.

## Changed functions and files

Only one new gameplay module was added: `js/game/30-positive-reputation-v0.7.3.4.js`, loaded immediately before `js/game/27-boot.js`.

The module wraps the following existing functions:

- `chooseEvent`: routes selected existing event/path outcomes through the shared cooldown ledger; existing direct positive changes are normalized rather than stacked on top of an extra reward.
- `doWork`: awards a small public-recognition bonus after a verified paid shift.
- `ir0724FarmWork`: routes its existing +1 into the shared 7-day ledger while preserving pay, experience, personal relationship memory, and the farmer's trust change.
- `ir0724HunterSell`: adds recognition only after an actual successful sale.
- `persist` and `normalizeSave`: preserve/normalize `world.v0734`, retain save schema 8, and update version metadata to 0.7.3.4.
- `shell` and `topbar`: update visible version metadata.

Existing occupation, combat, bounty, criminal group, loot, job payment, relationship, and reputation-system source files were not edited. `index.html` was changed only to update the game title and load the new patch. README, tests, and this report were added/updated for documentation.

## Rollback

The untouched v0.7.3.3 standalone backup is `backups/InfiniteRealms_v0.7.3.3_backup.html` and is also delivered separately as `InfiniteRealms_v0.7.3.3_backup.html`.

To disable only this patch in the source project:

1. Remove the script tag for `js/game/30-positive-reputation-v0.7.3.4.js` from `index.html`.
2. Delete that new patch file.
3. Restore the title/version text in `index.html` to v0.7.3.3.
4. Run `node build.js` to rebuild the previous source project, or open the untouched v0.7.3.3 backup standalone HTML.

The patch can be disabled independently because no pre-existing gameplay source file was modified. Save data may still contain `world.v0734`; the v0.7.3.3 game ignores that extra object. The standalone HTML backup is the safest complete rollback option.
