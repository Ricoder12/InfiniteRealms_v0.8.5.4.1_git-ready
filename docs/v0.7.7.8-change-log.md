# Infinite Realms v0.7.7.8 — Change Log

## Objective
Save compatibility and integration for the accepted v0.7.7.7 map and Character status interfaces, using the accepted v0.7.6.6 build as the pre-v0.7.7 baseline.

## Changes
1. Added `js/game/50-save-compatibility-v0.7.7.8.js`, which wraps the existing save normalizer and only fills missing optional fields. Existing valid arrays, object contents, character progress, and valid geography identifiers are not intentionally overwritten.
2. Added safe optional `world.known`, `world.visited`, and journal defaults when those properties are absent. Defaults are derived from existing current-site, discovered/visited records, and existing connected routes; it does not generate a new world or replace valid site IDs.
3. Added missing optional character containers for attributes, skills, inventory, equipment, relationships, NPCs, and discoveries. Existing valid properties remain present.
4. Initializes the existing `world.v0723` active-lead/history state during normalization and new-game initialization, preserving an existing valid lead store. This prevents the first map render from creating a save-state difference simply by lazily initializing that subsystem.
5. Resets transient map scope, selected geographic ID, and intelligence-origin flag when the top-level game state object changes. These are presentation state, not persistent world progress.
6. Adds the read-only `ir0778AuditSaveWorld` diagnostic helper for duplicate/ambiguous site IDs, geographic IDs, route IDs, and unresolved references.
7. Updated release title/badge and build docs to v0.7.7.8; added Node and Chromium save compatibility tests.

## Deliberately not changed
- No formal schema-version increment or migration.
- No world regeneration on save load.
- No replacement of valid saved geographic IDs, site IDs, or route IDs.
- No new progression or gameplay rules.
- No change to travel duration, cost, route ordering, or discovery mechanics.

## Validation summary
21/21 focused Chromium compatibility checks; 27/27 Node regression suites; 3/3 standalone smoke suites; 93/93 JavaScript syntax checks; 10/10 Python test scripts compiled; successful standalone build. Limitations are documented in `v0.7.7.8-test-report.md`.
